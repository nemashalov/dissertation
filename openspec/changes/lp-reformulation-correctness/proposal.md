# Критическое ревью: ЛП-переформулировка задачи размещения (гл. 3 §3.5)

## Why

Раздел 3.5 главы 3 переносит assignment-ЛП Янсена и Чжана [18] на задачу размещения эластичных задач по приоритету. Сверка с первоисточником `Scheduling malleable tasks with precedence constraints.pdf` выявила два независимых формальных дефекта, которые делают ЛП-переформулировку в текущем виде некорректной: (1) цитируемое свойство «не более двух соседних ненулевых переменных» доказано в [18] для ЛП минимизации длины расписания, а не для максимизационной упаковки с весами приоритетов; (2) целевая функция `max Σᵢ cᵢ Σₗ x_{i,l}` при ограничении `Σₗ x_{i,l} = 1` вырождена в константу `Σᵢ cᵢ` и не зависит от размещения.

## What Changes

- **Исправить целевое ограничение.** При `Σₗ x_{i,l} = 1` каждая задача размещается полностью, поэтому `max Σᵢ cᵢ Σₗ x_{i,l} = Σᵢ cᵢ` — оптимизация фиктивна. Требуется либо снять нормировку полного размещения (допустить частичное размещение), либо ввести в целевую функцию ресурсный вклад `l·p_i(l)` так, чтобы она зависела от размещения.
- **Уточнить/снять цитату свойства «двух соседних переменных».** В [18] свойство доказано для ЛП минимизации длины расписания `min C` с ограничениями предшествования (замечание к ЛП (10), с. 250–251). Для линейной максимизации над политопом fractional-assignment + ограничения ёмкости крайние точки в общем случае не обладают этим свойством. Приписывание свойства этому применению не поддерживается источником.
- **Перепроверить оценку аппроксимации.** Утверждение о «гарантированном ухудшении» и сертификате близости к оптимуму в batch-режиме справедливо только для корректной целевой функции; после правки целевой функции оценку нужно перевывести или явно ограничить областью применимости.
- **Явно отделить две парадигмы** (признак LP/C из `specs/notation-model.md`): минимизация makespan у [18] vs максимизация взвешенного объёма в данной работе — они не должны смешиваться.
