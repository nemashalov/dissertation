# Критическое ревью: «алгоритм заметания» неоптимален для заявленной цели (гл. 4 §4.2–4.3, введение, заключение)

## Why

В §4.2–4.3 главы 4 разрабатывается «алгоритм заметания» (sweep) для размещения эластичных задач по приоритету и утверждается его **оптимальность** для целевой функции

$$\max_x \sum_{i=1}^{n} c_i x_i, \quad \text{при} \quad \sum_{i=1}^{n} x_i \leq C, \quad x_i \in \{0\} \cup [x_{\min}, x_{\max}],$$

где `c_i` — приоритет задачи. Алгоритм состоит из двух фаз: (1) размещение в порядке убывания `c_i`, выделяя каждой задаче `x_min` до заполнения ёмкости; (2) обратное расширение до `x_max`. В §4.3 заявлено: «жадное размещение по убыванию приоритета является оптимальным». Этот тезис повторён как «положение на защиту» №2 («решает задачу оптимально за O(N log N)») во введении и заключении.

**Дефект: алгоритм не максимизирует `Σ c_i x_i`.** Противопример. Пусть `C = 100`, задача A `(c=100, x_min=40, x_max=100)`, задача B `(c=95, x_min=60, x_max=60)`. Фаза заполнения: A получает `x_A = 40` (остаток 60), B получает `x_B = 60` (остаток 0). Значение цели `100·40 + 95·60 = 9700`. Фаза расширения ничего не меняет (остаток нулевой). Оптимум: отдать всю ёмкость задаче A, `x_A = 100, x_B = 0`, значение `100·100 = 10000 > 9700`. Таким образом, жадный алгоритм даёт значение на 3% ниже оптимума.

Причина: наличие нижней границы `x_min` превращает задачу в дробную (непрерывную) задачу о ранце с минимальным «порогом» включения, где жадное заполнение всех `x_min` в порядке `c_i` неоптимально: оно принудительно тратит ёмкость на задачи с меньшим `c_i` (здесь B), хотя выгоднее отдать эту ёмкость задаче с наибольшим `c_i` (A). Стандартное решение непрерывной задачи о ранце (упорядочить по `c_i` и заполнять до `x_max`) не учтено; алгоритм максимизирует **число размещённых задач** (приём), а не **взвешенный объём** `Σ c_i x_i`, т.е. решает другую целевую функцию, чем заявлено.

## What Changes

- **Уточнить целевую функцию алгоритма.** Если алгоритм действительно максимизирует приём (число размещённых задач) с приоритетом как правилом разрешения, это надо явно сформулировать и не заявлять оптимальность для `max Σ c_i x_i`. Если цель — `max Σ c_i x_i`, алгоритм неверен (см. контрпример).
- **Либо исправить алгоритм.** Для `max Σ c_i x_i` с `x_i ∈ {0} ∪ [x_min, x_max]` требуется корректный метод (например, дробный жадный по `c_i` с заполнением до `x_max`, либо ЛП из §3.5), а не «заполнить все `x_min`, затем расширять».
- **Переформулировать «положение на защиту» №2** во введении и заключении: либо снять слово «оптимально», либо точно описать решаемую задачу.
- **Согласовать с §3.2** (там же декларируется «решать задачу оптимально за O(N log N)») и с §4.5 («минимизация длины расписания», «размещать задачи оптимально»).
- **Не смешивать с §3.5**: ЛП-релаксация в §3.5 и жадный алгоритм §4.2 решают разные задачи; правка должна прояснить, для какой из них что доказано.
